# RepoKernel Project Kernel Bridge

> Status: recent candidate / optional Seed capability.
> Scope: neutral distinction between project-kernel generation and meta-skill
> coordination.

## Purpose

RepoKernel and Meta Skill are both meta-level systems, but they should not be
merged.

```text
RepoKernel prepares a project repo so an AI coder can reenter and work.
Meta Skill decides which faculties, skills, competences and workflows should be
used in the current field.
Seed distributes the neutral contracts and install choices.
```

The bridge lets an installer, AI coder or external system understand when to
use RepoKernel as a project-kernel method without turning Meta Skill into an
installer or RepoKernel into an awareness faculty.

## Use RepoKernel When

Use a project-kernel method when a repo needs:

```text
entry gate;
current-state capsule;
source atlas;
semantic kernel;
process packets;
boundary rules;
reentry path;
memory-delta rule;
validation commands;
portable instructions for future AI coders.
```

## Use Meta Skill When

Use Meta Skill when the system needs to decide:

```text
which entity is active;
which surface owns the change;
which role each tool, skill, repo or product has;
which workflow should happen first;
which capability should be created, updated, used or ignored;
which update candidate is ready for promotion;
which boundary prevents semantic overlap.
```

## Bridge Rule

```text
if the problem is project reentry/autonomy, route to RepoKernel;
if the problem is entity recognition, capability orchestration or workflow
coordination, route to Meta Skill;
if the result is portable, route the neutral invariant to Seed.
```

## Seed Packaging

The Seed should not vendor private RepoKernel state or internal Meta Skill
memory. It should carry only:

```text
the distinction;
the routing rule;
the expected repo-kernel shape;
the validation expectations;
the profile metadata that makes the option visible to coder/dev-node/team
contexts.
```

This keeps external installation simple: a user can install the Seed once, then
select the project-kernel option only when a repo needs it.
